# Original-study correction report

This package contains the corrected original study. The published JSON was copied before source changes and remains byte-identical; stored paid LLM results also retain their pre-edit SHA-256 hashes. No LLM experiment was run.

## Trace convention

All paths below are relative to this directory. `R` = `outputs/results/results.json`; `P` = `outputs/results/results_published_original.json`; `A` = `outputs/results/published_audit.json`; `V` = `outputs/results/correction_verification.json`; `Q` = `outputs/results/validation.json` (recorded delivery checks). Dot paths are object-key paths, with numeric keys such as `0.3` treated as a single key, not array indices. For an unambiguous machine traversal, `V.changed_paths` stores arrays of literal keys. Tables round for reading; JSON retains full floating-point values. The report and verification are regenerated by `python scripts/run_experiments.py`.

## Changes and accounting

- `src/mas_sim/core.py::schedule_task`: optional decision time bounds every start without changing arrival times or waits. `make_private_jobs` and `tasks_with_private_work` generate and replay common private workloads.
- `src/mas_sim/mechanisms.py::run_ssi_auction`: schedules from the batch decision. The decision remains the last arrival in an offline-grouped 25-unit window, as in the supplied correction check, rather than the window's right edge. This convention uses advance knowledge of the last arrival; it is not a causal online timer implementation. All tasks nevertheless start at or after their actual modelled decision time. Window default: function signature.
- `run_cbba`: reuses the supplied check's retained bundles, drops the suffix after a lost claim, includes all held tasks in simulated queue time/position, and commits in bundle order. Counts actual sweeps, including the final stable sweep. A cap failure now raises instead of silently committing an unsettled allocation; no experiment hit the cap.
- SSI charges `B*n` task announcements, then `n` bids and one award for each of `B` allocation rounds: `B*(2*n+1)`. Each bid carries that agent's cheapest remaining task/cost; evaluating all alternatives is local work. This preserves the original message convention honestly; the count does not change with timing.
- CBBA charges `n*(n-1)` point-to-point winning-list deliveries per sweep and the existing modelled token cost per delivery. Initial batch availability and local commitment remain uncharged in this original convention. It is an ordered shared-winner-table adaptation, not a faithful asynchronous distributed implementation. Its stored token proxy remains fixed per list delivery regardless of bundle length.
- `run_contract_net`: adds a diagnostic fallback counter without changing published decisions or costs; see fallback audit below.
- `run_state_tracking_manager`: predicts queue-end position and busy-until from every award, using the same `Agent.estimate_cost` and stable tie-breaking as Greedy. It never reads private state except at explicit report points. `run_greedy_centralized` gains optional private-work replay and award charging used only in the new experiment. `src/mas_sim/__init__.py` exports the manager.
- `scripts/run_experiments.py`: adds Experiment 6, retains old seeds, adds all metrics to Experiment 4, and rebuilds all figures. `scripts/correction_report.py` verifies immutable claims and writes this report. `scripts/plot_llm_figure.py` is now a small saved-data-only wrapper.
- `tests/test_mas_sim.py`: regression tests cover both fixes, held-prefix overclaiming, consensus accounting/cap failure, fresh manager equality, private work, reports, seed determinism and the published fallback rule. `checks/baseline_corrections_check.py` now verifies corrected production results; its duplicate implementations are retired. `checks/measure_published.py` is the one-time original audit and refuses to overwrite its evidence.
- `src/mas_sim/llm_proxy.py`: removes the unsupported Agent Contracts reduction attribution from the docstring; all model constants and stored results are unchanged. `README.md` documents the revised reproduction flow.

## Experiment 6: when bidding pays

Parameters are at `R.experiment_6.params`: 12 agents, expected 200 public tasks from the original Poisson generator over horizon 500, and 30 paired trials. Public scenario seeds are 5000–5029; private seeds 15000–15029; CNP RNG seeds 25000–25029 (no noise or nonresponse is enabled). The original space, skills, speeds, workload and cost formula are unchanged. This follows the old experiment-specific seed-offset convention; it does not reuse Experiment 1's individual task streams.

For every agent, stationary private jobs arrive as an independent Poisson process with mean interarrival 25 time units. Service is exponential with mean `25*rho`, for offered loads rho in {0, 0.1, 0.2, 0.3, 0.5}; zero produces no jobs. Rho is expected private service demand per unit time, not the realized fraction of total busy time. Jobs are generated through the last public arrival, append to that agent's FIFO queue at their arrival, and do not move its queue-end position. Private arrivals win exact-time ties. The same immutable job list is replayed for every mechanism per seed/load; using the same private RNG seed across positive levels preserves event times and scales service durations. The manager knows initial agent state, public tasks and its awards, but sees private queue delays only in periodic reports before public task indices s, 2s, etc. (zero-based), with s in {1, 10, 50, never}. No report precedes task index zero. The manager schedules its forecast separately from the true FIFO queue. Live CNP bids and full polling use the true local queue; private jobs do not change the positions used for CNP invitation selection. All parameter values: `R.experiment_6.params`; per-seed public counts, private counts and service totals: `R.experiment_6.by_private_load.<rho>.workloads`.

Messages: manager = T awards + n*floor((T-1)/s) unsolicited status reports, or T for never. No queries, acknowledgements or completion reports are introduced. Reports contain queue-end position and busy-until; report timing is a public-task-index synchronization assumption, with no separate trigger message. CNP = k CFPs + k bids + one award = 11 per public task. Full polling = n queries + n replies + one award = 25 per task. The original experiments retain their published polling count of 2*n (24 at n=12), which excluded awards; this explicit convention difference changes no allocations. Counts are semantic deliveries, without packet-size or network-latency simulation. In this experiment all report and bid state is truthful.

Makespan is the latest public-task finish, wait is start minus public arrival (travel begins at start), and response is finish minus arrival, including travel/execution. Private-only completion after the final public finish is not a reported objective. Public tasks and private service demand are identical across compared mechanisms, though their queue ordering relative to public assignments and their incurred travel can differ. Each trial contributes equally to means and messages-per-task. Percentile bootstrap CIs resample trials 10,000 times with seed 123; paired CIs resample the per-seed manager-minus-CNP differences. These are pointwise intervals without multiple-comparison adjustment.

### Neutral reading (eight observations)

1. Fresh state makes the unrefreshed manager an efficient choice: it matches full polling exactly at 1 versus 25 messages/task, with wait 6.108 versus CNP's 6.936 (`R.experiment_6.by_private_load.0.0.aggregate.{Manager-never,Greedy-Centralized,Contract-Net}.{messages_per_task,mean_wait}.mean`).
2. At private load 0.1, refreshing every 10 tasks uses 2.163 messages/task with wait 11.304 versus CNP's 11.775; the paired wait difference is -0.471 [-1.551, 0.531], so the experiment does not establish a wait advantage (`R.experiment_6.by_private_load.0.1.aggregate.{Manager-10,Contract-Net}` and `.paired_manager_minus_cnp.Manager-10.mean_wait`).
3. At load 0.2, never refreshing gives wait 25.699 versus CNP's 21.625; the paired gap is 4.074 [2.350, 5.768]. Live bidding improves wait here at 11 versus 1 message/task (`R.experiment_6.by_private_load.0.2.aggregate.{Manager-never,Contract-Net}` and `.paired_manager_minus_cnp.Manager-never.mean_wait`).
4. At load 0.3, refreshing every 10 tasks gives wait 41.888 versus 38.016 for CNP; its paired gap 3.871 [1.257, 6.390] supports a wait benefit from bidding in this condition (`R.experiment_6.by_private_load.0.3.aggregate.{Manager-10,Contract-Net}` and `.paired_manager_minus_cnp.Manager-10.mean_wait`).
5. At load 0.5, never-refresh makespan is 813.917 versus CNP's 701.104, a paired gap of 112.814 [97.335, 130.034]; bidding substantially improves the last public completion (`R.experiment_6.by_private_load.0.5.aggregate.{Manager-never,Contract-Net}.makespan` and `.paired_manager_minus_cnp.Manager-never.makespan`).
6. That same high-load condition gives response 106.706 versus 105.545, whose paired gap 1.161 [-2.542, 4.771] includes zero; it does not establish a mean response advantage (`R.experiment_6.by_private_load.0.5.aggregate.{Manager-never,Contract-Net}.mean_response` and `.paired_manager_minus_cnp.Manager-never.mean_response`).
7. Refreshing every task costs 12.940 messages/task, more than CNP's 11; at load 0.5 its wait is 87.890 versus 80.910. Live state alone does not make a myopic all-agent choice optimal (`R.experiment_6.by_private_load.0.5.aggregate.{Manager-1,Contract-Net}.{messages_per_task,mean_wait}.mean`).
8. Managers with infrequent reports remain the lowest-message choices; bidding is attractive where its measured delay or makespan improvement justifies extra communication. No single method dominates every metric and load; the complete pointwise intervals above define the evidence.

## No-responder rule and audit

If all invited candidates drop the CFP, the original code takes true costs from the same nearest invitees, selects the cheapest, and charges only the already sent CFPs plus the award. It does not contact all agents, charge a second announcement, charge synthetic bid responses, or apply fresh quote noise in that fallback. This is an uncharged local-state lookup assumption, not communication-free recovery that a distributed implementation could generally guarantee. The fallback counter is diagnostic only.

Before edits, it fired 9 times among 4059 public tasks (0.222% rounded), all in the 30%-nonresponse condition (`A.fallbacks["experiment_5.nonresponse.0.3"].{fallbacks,n_tasks}`; percentage `V.fallback_counterfactual.percent_tasks`). Charging one full-team re-announcement and replies would add 216 messages overall, or 10.8 per trial (`V.fallback_counterfactual.{extra_messages_all_trials,extra_messages_per_trial}`). That changes published CNP results, so the hard preservation requirement selects documentation rather than charging.

Figure identifiers retain the original numbering.
- `fig2_strategy_comparison`, `fig3_load_distribution`, `fig6_token_proxy` use `R.experiment_1`; `fig4_scalability` uses `R.experiment_2`; `fig5_ablation_k` uses `R.experiment_3`; `fig8_optimality_gap` uses `R.experiment_4`; `fig7_robustness` uses `R.experiment_5`; `fig10_when_bidding_pays` uses `R.experiment_6`. Error bars in the original experiment figures are SD; the new experiment uses 95% bootstrap CIs; all have been regenerated. Each filename is under `outputs/figures/`.
- `fig9_llm_live` only reads `outputs/results/llm_sweep_n{8,16,24}.json`: tokens/task = sum(`trials[*].{llm_cnp,llm_centralized}.llm.total_tokens`)/sum(`trials[*].<method>.n_tasks`); makespan = mean(`trials[*].<method>.makespan`). No paid experiments were rerun.
- Every non-SSI/CBBA published value reproduced exactly. The expected corrected baseline numbers also reproduced. The old low-communication headline remains an advantage over per-task full polling, not over a fresh state-tracking manager.
- The fresh Experiment 6 absolute means differ from Experiment 1 because they use a new seed block; this is intended. Manager s=1 can differ slightly from full polling with private work because its first task has no report; a private job can arrive before that task. Subsequent decisions may follow different trajectories. Fresh-state equality remains exact.
- More frequent reports do not monotonically improve all metrics; allocation is myopic, and different choices change travel and future queues. CNP can improve on full polling under load for the same reason. This is an observed simulation result, not evidence of optimality or a general dominance claim. Offered private load is not a measured utilization percentage, and private work here changes queue time but not location.
