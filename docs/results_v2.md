## Live LLM: worked variant, reference conditions and additional models

Generated from the saved per-model result files by `src/mas_sim/llm_report.py`. All models use the same scenarios, seeds, k=3 capability shortlist and scheduler as the one-shot gpt-4o-mini run, temperature 0, and (for the new runs) the same prompt facts. **One-shot** requires a bare JSON answer (128-token cap). **Worked** asks for brief step-by-step working and ends with the same JSON object on the final line; the last JSON object is parsed with the same strict validation, and a response cut off by `max_tokens` (`finish_reason` = length) counts as invalid. `shortlist_random` and `shortlist_top1` are zero-cost references: a seeded uniform pick from the same three-agent shortlist, and its first entry, with no bids. The formula conditions compute the bid exactly. Entries are mean [95% Student-t CI over trials]; there are five trials per group, so intervals are wide. Token counts are provider-billed `usage` tokens. Truncated rate for the original one-shot gpt-4o-mini run is inferred from completions that used the whole 128-token cap (finish_reason was not stored then). Latency is summed API seconds per task, original latency when replayed from cache. Trials run in parallel threads in the new runs, so latency is not inflated by queueing between trials.
