# v2 model notes

v2 is the default `ScenarioConfig` and `scripts/run_all.py` configuration. The recovered behavior remains available as `ScenarioConfig(version="legacy")`, the original compatibility APIs, and `python scripts/run_all.py --version legacy`. All 30 recovered trials are regression-tested without changing expected results. [Legacy notes](model_notes_legacy.md) preserve the provenance and previous weaknesses. No command runs against the recovered OneDrive directory.

The contribution is an empirical information-policy and accounting comparison, not a new Contract Net Protocol. Names are **manager-mediated bounded CNP**, **full-information greedy** (myopic, not an optimum), and **cached central**. See [literature review Section 4](research/literature.md).

## Scenarios and scheduling

Defaults: 12 agents, five skill types, 100 x 100 workspace, expected 200 Poisson arrivals over H=500, k=5, 25-unit batch windows. The second load is expected 300. Agent skills, speed U(0.8,1.3), location, and workload U(2,10) distributions are unchanged. Default theta=0 means soft proficiency: every agent can perform every task, at different service rates.

`SeedSequence(seed).spawn(4)` creates separate streams for agents, managed tasks, protocol randomness, and private jobs. Trials use seeds 0-29. Fixed-load team-size comparisons share identical tasks and nested teams. Proportional E2 uses expected tasks=(200/12)*n without rounding the Poisson rate. V2 permits empty Poisson streams; legacy alone forces a positive-rate stream to contain a task.

All mechanisms reuse `domain.execute`: serial, nonpreemptive FIFO queues. Dispatch=max(arrival, decision, previous committed finish); travel=Euclidean endpoint distance/speed; execution=workload/max(skill,0.05). No pre-travel before release/decision. Position is the committed queue endpoint, not current physical position. Service begins after travel. Bid=remaining backlog+travel+execution. Communication has zero simulated delay. API wall-clock latency is measured separately and does not alter simulator execution time.

## Registry and symmetric physical messages

Every trial pays n initial registrations, even policies that do not use the registry for routing. A static capability card publishes skills, speed, initial endpoint and finish. The registry retains last-published endpoint/finish, not the queue list. Reads of this colocated manager directory are in-process, with no network message: an explicit centralized information assumption.

After every s-th managed award per winning agent, registry-dependent policies send one update with endpoint and committed finish. s=1 is fresh; s=None is never. Unpublished awards leave the directory unchanged. All policies pay an assignment/award for each task assigned. Registry-independent policies do not send unused updates.

| Policy | Per served task, fresh state, excluding n registrations |
|---|---|
| CNP nearest/capability, clean first round | k CFP+k bids+1 award+1 status=2k+2 |
| CNP random | k CFP+k bids+1 award=2k+1; no registry state or updates |
| Full-information greedy | n queries+n responses+1 assignment=2n+1; no updates |
| Cached central | 1 assignment+1 status=2 |
| Nearest-agent | 1 assignment+1 status=2 |
| Round-robin | 1 assignment |
| SSI | For B-task batch: nB CFP+nB vector bids+B awards=(2n+1)B; no registry updates |
| CBBA | n(n-1) directed consensus deliveries per synchronous round, plus one final assignment/task; no registry updates |

SSI uses live vector bids, recalculated after each award. CBBA uses live bundle claims/winner vectors, releases losing suffixes and requires an unchanged conflict-free covering round. Neither reads the registry after initialization. Full mesh, append-only bundles and synchronous rounds are implementation choices, not universal CBBA costs/guarantees.

The assignment envelope includes the task body for all methods, so RR/NA/CC can execute without a preceding CFP. CNP/SSI repeat it for a common dispatch schema. Execution results, acknowledgements, transport handshakes, registry replication and authentication traffic are uniformly excluded. JSON-RPC-style events are counted once; bids/state responses are the actual replies. Initialization is included in all reported rates. Vector incidences are not summed as physical transmissions.

## Information rules, failures and private jobs

Nearest ranks registered endpoints by distance. Capability ranks registered travel+workload/registered skill, with id tie-breaking. **It never reads registry finish or actual backlog for shortlisting**, although finish is available to cached central. The bid includes actual local backlog. Random samples a uniform permutation and probes successive groups of k without replacement; it uses no registry state.

Cached central minimizes max(0,registered finish-now)+registered travel+execution. With fresh updates and no private work, it makes exactly the same assignments as polling greedy at far lower message cost. This is a meaningful counterexample to general bidding-versus-centralization claims.

All-silent/ineligible rounds re-announce to the next k under the same ordering, charging every CFP/reply/decline. A nonrespondent sends nothing; no timeout duration is modeled. Each candidate is considered at most once. Exhausting the team leaves the task unserved; no omniscient fallback exists. Realized-cost re-bidding is rejected in v2 and preserved only in legacy.

E3 hard eligibility theta=0.6 allows primary-skill agents only. An ineligible invited agent sends a charged decline. Capability filters by registered skill before inviting; nearest/random discover incompatibility through declines. No eligible agent means unserved, never assignment through the proficiency floor. All other experiments use theta=0. Hard eligibility for batched SSI/CBBA is outside this experiment and explicitly rejected.

E6 adds Poisson private jobs at rho times the managed rate, rho in {0,0.25,0.5,1}, with the same workload/location/skill distributions and uniformly random agent owners. Private jobs append directly to queues with no registry messages. Streams/owners are identical across policies for a seed/rho. Private arrivals and managed arrivals/batch closures are interleaved chronologically (private first on exact ties). A later managed update reveals the endpoint/finish including already queued private jobs; private information is not permanently hidden. Quality/fairness loads concern managed work only. Private jobs delay managed work but do not enter managed message/token denominators.

## Serialized sizes

`wire.py` provides concrete compact JSON-RPC 2.0-style card registration, CFP (task id, required skill, workload, location, arrival, null deadline), bids/vector bids, declines, assignments, updates, live-state queries/responses, and bundle/winner consensus. These are **A2A-inspired example schemas, not A2A conformance claims**. Transport routing metadata is recorded outside the envelope. Request ids are transport-pair scoped. Numeric wire values have six decimal places; execution uses full precision.

Centralized responses carry skills, speed, endpoint, committed finish and the outstanding queue (including executing work until finish), not full history. Each queue item contains task data, service start and finish. Every ledger message is serialized and counted with `tiktoken/o200k_base`; a bounded cache reuses identical string counts without removing messages. Vector lengths therefore affect size. Mean tokens/type and physical bytes are saved. The fallback, if tiktoken cannot load, is ceil(UTF-8 bytes/4), explicitly identified in metadata. The actual run uses tiktoken.

Wire tokens are control-plane sizes, not provider-billed inference. Payload sensitivity saves `outputs/v2/results/token_sensitivity.json` and the requested copy at `outputs/results/token_sensitivity.json`. It reserializes primary seed-0 responses at queue lengths {0,1,2,5,10,20,50,100}, truncating/cycling observed items, and scales measured CFP totals by {0.25,0.5,1,2,4,8}. Allocation is fixed. Fractional CFP sizes are counterfactual context sizes, not claims of a valid compressed envelope. Cached central is included. Reference fetching, shared-context caching and downstream reasoning can change real costs.

## Metrics and statistics

Report makespan, mean response (arrival to completion), mean/p95 wait (arrival to service start, including travel), managed-work Jain fairness, messages and tokens per managed arrival. Unserved rate, declines and re-announcements are explicit. Duration metrics are conditional on service: lower duration with more unserved jobs is not better quality. Private completions after the final managed completion do not extend makespan. Queue-only wait, last arrival and drain time remain diagnostics. Legacy-named token fields in v2 are aliases of measured wire tokens; legacy latency/context-pressure proxies are not reported as v2 findings.

All simulation points use 30 trials, sample SD ddof=1 and Student-t 95% CIs for means. Trials, not correlated tasks, are the inference unit. Paired differences use 10,000 percentile bootstrap resamples, seed 12345, of trial percentages 100*(CNP-reference)/reference; absolute paired differences are saved too. The **pre-specified +/-5% margin** applies to makespan and mean response against greedy and cached central. A comparison is flagged within-margin only when both 95% CI endpoints lie inside it. This interval rule is not a formal preregistered TOST study. Broad sweeps are descriptive; no multiple-comparison adjustment is applied.

## Exact optimum

E4 uses four agents, the first at most eleven managed tasks from the primary stream, and CNP k=2. The solver minimizes **makespan only**; no response-time optimum is claimed. It enumerates all subset routes with exact earliest-finish dominance, then all task partitions by branch-and-bound. Constraints: every task served exactly once; serial nonpreemptive service; actual heterogeneous speeds, travel and skills; release times respected; no pre-travel; no imposed batch waits; no private jobs; no communication delay. It sees future tasks and may reorder each agent's route. Gaps therefore combine online information loss, batching and allocation choices. Earliest-finish dominance cannot simply be reused to optimize total response time. Independent brute-force small-instance tests verify this solver.

## Small live LLM replication

The runner reads only the repository `.env` entry `OPENROUTER_API_KEY`, without printing/logging/copying/writing it. Model `openai/gpt-4o-mini`, temperature 0, JSON output, 128 completion-token cap. OpenRouter catalogue prices checked on 2026-11-12: input $0.15/million, output $0.60/million; provider price ceilings pin these rates. Dry run must estimate under $2; twenty live smoke calls precede full execution. Hard limits across reruns are $4 and 6,000 attempts.

Before each call it persists a conservative input-byte-plus-overhead/output-cap reservation. Returned `usage.cost` replaces it. Missing trustworthy cost stops the run; ambiguous failures/interruption retain a reservation rather than assuming free calls. Actual spend and unresolved reservations are separate. Cache keys hash the entire API request, including prompts/model/provider settings. Cache saves requests and sanitized response/usage/latency, never headers or credentials. Successful and failed cached outcomes replay without spend; `run_all.py` is cache-only and explicitly fails on missing responses.

Responses must parse as JSON with a finite nonnegative numeric bid or an integer team agent id; booleans and numeric strings are invalid. One retry/backoff is allowed. Then exclude that bidder; if all fail, or centralized routing remains invalid, mark unserved. Never substitute the formula answer. Every invalid/network failure is recorded. Calls without returned usage are explicitly counted; their token contribution is unknown, so measured token totals are lower bounds when such failures occur. The initial live runner recorded one PermissionError after charging usage in its cumulative journal but before saving that call's token details; the allowed retry succeeded. Its exact cause was not retained. The missing per-call cost is reconciled as the journal residual, but missing tokens are not invented. Windows atomic-file replacement retries in the corrected runner are local disk retries, never additional paid calls. A journal write failure stops the run. Model prompts describe waiting, travel and proficiency-dependent execution without precomputed bid answers.

Main: n=8, expected 30 tasks, five trials. Sweep: n={8,16,24}, expected 20, five trials each. H=500, CNP k=3 capability shortlist. Bidders see only the task and their own local state; centralized sees the team. All four conditions replay shared scenarios through the same scheduler. Agreement uses the formula choice on the **LLM trajectory's current state and shortlist**; bid error is mean absolute relative error among valid bids. API input/output tokens, sequential API latency, validity, agreement and schedule quality are reported with trial-level CIs. Cache replay reports original API latency and usage, not disk latency. Identical requests across conditions may share a cache entry; per-condition logical-call metrics reuse measured usage while actual cumulative spending counts each fresh request only.

This is a **small arithmetic-routing replication, not an LLM-agent benchmark**. In the bidding condition the k=3 shortlist is computed by the deterministic capability formula, so the LLM only re-ranks the formula's top three, whereas the centralized LLM chooses among all n; the smaller quality loss of LLM bidding partly reflects this pre-filter. The audit ([audit_v2.md](audit_v2.md)) found the prompt complete and the parser correct; bid errors are model arithmetic errors (median absolute relative error about 0.69, about 10% zero bids). The LLM estimates synthetic durations; it does not execute semantic work, learn skills, retrieve context or use tools. Sparse 20-30-task loads do not test sustained contention. The prompt supplies ordered skill arrays and integer required_skill but leaves the zero-based indexing convention implicit; this ambiguity may contribute to arithmetic/routing errors. No prompt optimization was performed after seeing results. Temperature zero does not guarantee cross-provider determinism; saved responses are the reproducibility boundary. Wire tokens, billed API tokens, simulator time and physical API latency are distinct.

### Worked variant, reference conditions and additional models

The one-shot run above is kept exactly as it was (its request hashes, cache and aggregates are unchanged). Alongside it there is a **worked** prompt variant for both LLM conditions. The system text is the same except for its last sentence: the model must show brief step-by-step working (bidding: waiting, travel and execution time separately, then the total; centralized: those terms and their sum for each agent, one short line per agent, then the choice) and end with the same JSON object on the final line. There is no `response_format`; the **last** JSON object in the reply is parsed with the same strict validation (finite nonnegative number, or an integer team agent id). `max_tokens` is 2,048 for a bid and 8,192 for a centralized call (a first pilot cap of 4,096 came within 2% of truncating an n=24 answer, so it was raised before the full run). A response whose `finish_reason` is `length` counts as invalid and is reported as truncated; the single retry and the documented fallback are unchanged. Temperature 0, scenarios, seeds, k=3 shortlist and design are those of the one-shot run, so the variants are paired by scenario (trajectories still diverge because the model's choices change the queues).

Two zero-cost references use the same shortlists: `shortlist_random` awards to a uniformly random member of the three-agent shortlist (seeded by the scenario seed) and `shortlist_top1` to its first entry, with no bids and no calls. They show how much of the result is the formula pre-filter rather than the model.

Every model uses its own spending journal (`outputs/v2/llm_cache/budget_<model>.json`) and result files (`outputs/v2/results/llm_<model>_*.json`); the cache is shared and keyed by the full request, so no existing entry is re-billed. Trials run in parallel threads (the journal is lock-guarded; calls inside a trial stay sequential). Each model had a dry-run estimate, a 20-call smoke test spanning both prompts and the largest team, and a check of the key's cumulative usage (`/api/v1/key`) before and after; the project total was capped at USD 8.00 and the final key usage is in the generated live section of [results_v2.md](results_v2.md). Per-call `usage` is trusted; billed reasoning tokens were zero for every call.

Models were chosen from the OpenRouter catalogue fetched 2026-11-12 (prices USD per million input/output tokens): `openai/gpt-4o-mini` (0.15/0.60), the original model; `google/gemini-3.1-flash-lite` (0.25/1.50), the current non-preview small Google Flash-class model that lists temperature support, with no billed reasoning tokens (no reasoning switch is sent); `meta-llama/llama-3.3-70b-instruct` (0.71/0.71), a widely deployed open-weight dense chat model an organisation can host on a small GPU node and that has no reasoning mode. `anthropic/claude-haiku-4.5` (1.00/5.00) was the first choice for the other vendor, but its estimate for the worked sweep (about USD 6, because of its output price) would have taken the project over USD 8, so it was **skipped**; the newer `anthropic/claude-haiku-5.5` lists no temperature support, so it cannot run at temperature 0. The two additional models were run on the team-size sweep and on the main design (all five trials each). For these models the one-shot reply may be wrapped in a markdown code fence (no reply from either model was actually fenced); one surrounding fence is stripped before the same strict validation and any stripped reply is flagged per call. Provider routing on OpenRouter, quantization and tokenizers differ between models, so token counts compare billed usage, not a common tokenizer. Llama's 7 invalid attempts were all dropped connections (six `ConnectionResetError`/`URLError` on worked centralized calls, one on a worked bid) with no usage returned; the retry and fallback rules handled them like any other invalid response, and their conservative reservation (USD 0.08) stays in its journal. Gemini and gpt-4o-mini had no invalid or truncated attempts.

The finding to carry over is about what the one-shot run could and could not show: with working, bids are accurate for all three models and the formula-pre-filtered bidding design nearly matches the formula, so the one-shot error was arithmetic, not coordination. But working multiplies tokens about threefold, and the saving of bidding over centralization shrinks or reverses at n=8 (see the paired tables in [results_v2.md](results_v2.md)). Both runs use a synthetic arithmetic task with a deterministic shortlist; neither is a semantic agent benchmark.

## Remaining weaknesses

- Static advertised skills are true synthetic service rates. Capability uncertainty, incentives, execution failures, churn and strategic misreporting are absent.
- A central directory has free local reads and instantaneous chosen updates. Registry infrastructure/replication/privacy costs are absent. Publishing committed finish may be unacceptable in some systems.
- Greedy only optimizes each current decision; CNP can beat it over a whole schedule without a global guarantee. Compare against cached routing and randomized probing, not protocol labels alone.
- Private work has independent, homogeneous arrival intensity; managed updates reveal accumulated private backlog. Other secrecy/ownership models may differ.
- Busy-time fairness can reward wasted travel. Served-only durations and small-instance gaps do not establish universal quality.
- Full-mesh CBBA, compact envelopes, and context payload policies are choices. Incremental deltas, shared references and network broadcast can change cost rankings.
- Confidence intervals concern these synthetic populations. Fixed-load team gains partly reflect less work per agent; the proportional-load sweep is included to expose that effect.
